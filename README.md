# Open-Box Patch

为 [Open-Box](https://github.com/liandu2024/Open-Box) 浏览器面板提供多后端管理、集中版本维护和概览地图。支持 OpenWrt、Debian 和 Ubuntu。

## 功能

- **多后端切换**：保留主面板的前端页面，读取所选服务器的策略、连接和设置。
- **当前后端标识**：在左下角后端管理器显示名称，并用面板主题强调色选中当前后端。
- **拖动排序**：拖动 ⠿ 调整远程后端顺序，支持鼠标和触屏，自动保存；本机前端固定首位。
- **版本管理**：集中查看各服务器的 OpenBox 和 Patch 版本，支持检查版本、单台及批量更新。
- **批量重启**：勾选服务器后重启其 OpenBox 内核，各服务器分别显示操作结果。
- **共享网络兼容性**：启用启动完整性校验的 OpenBox 使用原版共享网络，暂停 AnyTLS／Hy2 高级注入。升级补丁会核验并还原此前注入修改的原版文件，保留多后端管理与地图功能。
- **出口分流**：在独立的出口分流页面为代理流量选择 Wan1，为直连流量选择 Wan2（支持独立网口或同网桥双网关）；应用后校验分流是否真的生效，**校验不通过内核不会启动**。
- **设置入口**：OpenBox「设置 → 后端设置」可查看和更新当前后端的 Patch。
- **概览地图**：概览页显示全球连接、端点归属和连接线路；本机 IP 与地图起点取自当前后端，DNS 设置页不显示地图。
- **线路分类**：按实际出站配置把每条连接判为**直连 / 经代理（单跳）/ 经中转（经中转再代理）**。判定只看链路本身，与「显示中转」开关无关；「经中转再代理」里的中转节点与落地节点分开标记，不会和「本机经代理」混成一种颜色。
- **按链路画线**：直连一路画到目的地；经代理 / 经中转只画**流量实际经过的代理链路**（… → 落地节点），终点是最后一个代理节点，不再多画一条到最终目标的线。
- **地图记忆与中转**：自动记住 2D／3D、地图样式、城市标签、自转及中转显示设置；开启「显示中转」后把中转节点画到地图上，图例包括本机、直连、经代理／落地节点、经中转／中转节点。

## 安装与更新

先安装 Open-Box，再以 root 权限运行以下命令。更新补丁使用相同命令，保留已有代理配置。

直连 GitHub：

```sh
curl -fsSL https://raw.githubusercontent.com/xhy200606/Open-Box-Patch/main/install.sh | sh
```

通过镜像下载：

```sh
curl -fsSL https://gh-proxy.com/raw.githubusercontent.com/xhy200606/Open-Box-Patch/main/install.sh | sh -s -- --mirror
```

Debian / Ubuntu 普通用户将上述 `sh` 替换为 `sudo sh`。安装后刷新主面板。

本地安装及常用参数：

```sh
sh install.sh
sh install.sh --proxy-port 3037
sh install.sh --proxy-token <代理口令>
sh install.sh --panel-url http://127.0.0.1:3036
sh install.sh --platform openwrt
```

每台需要远程更新 Patch 的服务器，先安装一次支持版本管理的补丁。代理使用其他端口、HTTPS 或访问口令时，在该后端的编辑页填写对应信息。

## 使用

1. 点击左下角「后端」管理器的 ⚙，添加服务器地址、名称和面板密码。
2. 点击服务器切换后端。左下角名称和强调色同步更新，页面读取该服务器的数据。
3. 打开管理列表，拖动 ⠿ 调整顺序；勾选服务器后选择批量更新或批量重启。
4. 更新和重启前会列出所选服务器供确认。批量重启操作针对 OpenBox 内核。
5. 在「设置 → 后端设置」查看当前后端的 Patch 版本和更新入口。

### 出口分流

打开「设置 → 出口分流」，确认当前后端，分别选择代理网络的 Wan1 和直连网络的 Wan2。该入口与「后端设置」位于同一层级；主前端和目标后端均需升级 Patch 至支持自动路由的版本，刷新页面后可见。这里选择的是系统网口名称（例如 `eth0`、`pppoe-wan`），先在 OpenWrt 或 Linux 中配置好 WAN 的 DHCP、拨号或静态地址。勾选「自动配置路由表与策略规则」后，补丁会识别网关并完成策略路由，无需手动添加路由表；不会把管理 LAN 改成 WAN，也不改变系统主路由表。

- **同网桥双网关**：中心路由与两台上游可以共用一个网段。启用“同网桥双网关分流”，两个出口选择同一 `br-lan`，启用自动路由并填写两个不同的 IPv4 上游网关。补丁会在该网桥上挂两个辅助源地址（默认 `.221` 代理、`.222` 直连，取相同 `/前缀`），代理出站绑定 `.221`、直连出站绑定 `.222`，内核按源地址走不同的策略表。**不使用出站标记**——`routing_mark` 与 sing-box 的 `tun.auto_redirect` 硬互斥，同时存在会让所有出站连接直接失败。不增加 NAT、不修改 DHCP、网桥或主路由表；终端默认网关应指向中心路由。未填写 IPv6 上游时阻断该模式的 IPv6 外网回退。
- **自动策略路由**：Wan1 使用表 `22031`／规则优先级 `8701`，Wan2 使用表 `22032`／优先级 `8702`；按内核已绑定的出口网口查表，兼容 OpenBox 的出站标记。检测到表或优先级被其他程序占用时拒绝覆盖。
- **自动网关**：从系统路由和 OpenWrt 网络接口识别 DHCP、拨号与 IPv6 网关；特殊网络可在高级选项填写覆盖值。每 15 秒检查网关与地址续租变化。IPv6 无上游时为该出口设置不可达默认路由，避免回退到另一条 WAN。
- **停用与恢复**：只清理补丁拥有的规则和路由，并恢复所选 WAN 的反向路径校验设置；保留管理 LAN、VPN 和其他程序的路由。系统需提供支持 JSON 输出的 `ip`（OpenWrt 为 `ip-full`）。
- **保存草稿**：只保存选择，不改变网络；第二个网口尚未接入时可以先保存。
- **应用并重启内核**：先由本机 sing-box 校验配置，再通过原生接口部署并重启，**随后校验分流是否真的生效**：运行配置里必须分别有出站绑定到 Wan1 与 Wan2、`route.default_interface` 必须是直连出口、且不能有漏绑的出站；在 Linux 上还会确认**内核进程确实跑在这份配置上**。任一条不通过就报失败。
- **失败即拒绝启动（fail-closed）**：网口未就绪、独立网口模式下两项选择同一网口、校验不通过或内核被原生方式拉起（绕过包装脚本）时，**内核不会启动/会被停止** —— 宁可不启动，也不让流量从错误的出口出去。失败原因会写进 `data/multi-backend/egress-last-error.json` 并显示在设置页。
- 设置页顶部会显示真实状态：**分流已生效 / 已启用但未生效 / 未启用**，并列出两个出口的绑定出站数、默认出口、内核进程与最近一次校验问题。
- 启用时自动关闭原生「直连绕过」。终端绕过和端口绕过需先在原生设置中关闭，否则拒绝应用；停用后如需直连绕过，可自行重新开启。
- **fakeip 回灌 TUN**：如果 DNS 里配了 `fakeip`（域名被解析成 `198.19.x`），补丁会把该网段写进 TUN 的 `route_address`。否则客户端拿着 fakeip 会按系统默认路由从直连出口发出去 —— 内核侧看起来一切正常，客户端却访问不了被墙域名。
- 当前支持通过 sing-box 出站发起的网络连接；暂不支持含独立 `endpoints` 的配置或经本机其他代理进程转发的出口；OpenBox 自身的本地 DNS 回环服务保持原有路径。系统其他应用及明确绕过 OpenBox 的流量仍由系统路由决定。

出口分流使用独立配置与服务启动包装器，不修改受校验的 OpenBox 服务端文件或校验清单。每次内核启动都会从最新原生配置生成并校验运行配置。补丁重放服务会重新接入更新后的受支持启动脚本；上游启动格式变化时报告不兼容，需要更新补丁后再应用。每台使用此功能的后端都需要安装新版 Patch，并启用面板管理员认证或配置代理口令。

### 概览地图

概览地图首次使用需在卡片中下载城市数据库，然后显示活跃连接的 IP 归属。地图仅出现在概览页。
概览页最底部还有一张「出口分流」卡片：显示是否真正生效、两个出口的网口与地址、最近一次应用结果，
以及直连 / 代理各自的连接数、上下行速率与流量占比。

地图颜色表示线路类别：**青=经代理**（单跳）、**紫=经中转**（经中转再代理）、**橙=直连**，白点为本机。
直连一路画到目的地；经代理 / 经中转只画链路本身（如「本机南京 → 中转上海 → 落地东京」画成
`南京→上海→东京`），**终点停在最后一个代理节点，不再画到最终目标** —— 于是同一代理下的所有连接
会合并成一条线，地图更干净。开启「显示中转」可把**紫色中转节点**也画出来（落地节点是链路终点，始终画）。
把鼠标移到端点上可看到它的角色（本机 / 中转节点 / 落地节点 / 目的地）、所属线路类别、连接数，
以及**流经该落地节点的下载量 Top5 Host**。

## 卸载

旧版共享网络扩展创建的 AnyTLS 配置需删除后才能由原版管理；Hy2 使用上游默认设置。补丁会先核验原版备份，再还原共享网络文件。

以 root 权限运行：

```sh
curl -fsSL https://raw.githubusercontent.com/xhy200606/Open-Box-Patch/main/uninstall.sh | sh
```

本地卸载：`sh uninstall.sh`。

## 开发

修改地图源码后构建：

```sh
cd frontend/globe
npm install
npm run build
cd ../..
```

先在仓库根目录运行 `npm ci` 安装 DOM 回归测试依赖；地图测试还需按上面的步骤安装 `frontend/globe` 依赖。运行模拟服务器集成测试与语法检查：

```sh
node --test tests/*.test.mjs
node --check frontend/multi-backend.js
node --check backend/proxy.mjs
sh -n install.sh scripts/apply.sh scripts/update-patch.sh
```

安装入口保持在仓库根目录，原有 GitHub 安装、更新链接继续可用。
